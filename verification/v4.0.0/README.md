# LELE 4.0.0 大文件验证

四类读入均走 LELE 的正常文件入口。原子坐标使用 float64，CUBE 标量使用 float32。测试环境为 Linux x86-64、Python 3.12.14、NumPy 2.3.5、SciPy 1.17.0、ASE 3.29.0、PySide6 6.12.0 和 VTK 9.7.2。完整回归通过 2,379 项及 78 项子测试，14 项需要未随包分发的外部样例。逐项结果见 [regression.xml](regression.xml)。

## 打开文件

以下为 v3.18.0 与 v4.0.0 使用相同合成文件的三轮中位数。每次新建进程，先用小文件预热对应入口。每轮交替运行两个版本，第二轮倒序，系统文件缓存未清空。峰值为完成打开时的进程 RSS，包含解释器和已加载依赖。哈希校验在计时和读取峰值之后进行。

| 输入 | v3.18.0 秒 | v3.18.0 MiB | v4.0.0 秒 | v4.0.0 MiB |
| --- | ---: | ---: | ---: | ---: |
| CUBE，400³，0.96 GB | 5.83 | 312 | 1.94 | 311 |
| CUBE，416³，1.08 GB | 仅读取原子 | — | 2.30 | 342 |
| OUTCAR，200.01 MiB，5,678 步 × 500 原子 | 7.73 | 725 | 3.68 | 230 |
| XDATCAR，10,000 步 × 500 原子 | 2.84 | 375 | 1.47 | 146 |
| CP2K XYZ，10,000 步 × 500 原子 | 2.93 | 393 | 1.64 | 146 |
| WAVECAR，3.00 GiB，配 POSCAR | 1.71 | 78 | 0.10 | 74 |
| 同一 WAVECAR，仅配 200.01 MiB OUTCAR | 9.63 | 764 | 1.47 | 85 |

- CUBE 测试验证全网格形状和 float32 字节摘要。416³ 含 71,991,296 个标量。两个版本都能读取的 400³ 数据逐字节一致。416³ 另核对生成公式所得的完整数据摘要。
- OUTCAR 索引保存原始行号。所有已显示结构、逐帧晶胞、能量、力的收敛统计和步号都参与对比。另测 UTF-16、多个连续 VASP 作业、残缺尾帧和 VASP NMR。单独查看 WAVECAR 时，若有唯一且晶胞匹配的 OUTCAR，可选取最后一个完整结构。
- AIMD 的两种源文件分别约 185 MB、198 MB。首次导入时逐帧解析并验证。对于此测试，紧凑的临时坐标文件占 120,000,000 字节，约 114.4 MiB。源记录与显示帧各自通过私有映射访问相同底层文件，修改某一帧时两者保持独立。临时文件在映射释放时回收。系统文件缓存和磁盘占用另计。另对完整 XDATCAR 做项目往返验证。在第 7,013 帧修改第 14 个原子，移走输入文件后保存 .lele，再用独立进程重新打开。全部 10,000 帧的源坐标和编辑坐标分别通过完整摘要核对。
- WAVECAR 使用 2 个自旋、8 个 k 点和 337 条能带。波函数系数按指定能带定位。检查全部自旋和 k 点的**有序** G 向量、最后一条能带的 113³ 密度以及另一个多平面波测试的解析实部、虚部和密度。带 POSCAR 时，重建该单态密度从 0.204 秒降到 0.098 秒。保存的项目仍从原 WAVECAR 按需读取系数。

## 显示与交互

- 对单独生成的 400³ 光滑场取等值面 0.2，保留 402,380 个三角形，两个版本的顶点坐标摘要相同。首次生成耗时从 1.51 秒变为 1.36 秒。同场同阈值再次构建场景从 1.00 秒降到 0.16 秒。两次构建的进程峰值从 915 MiB 降到 679 MiB。表面网格所占内存还取决于实际场形状与阈值。
- 10,000 × 500 的 XDATCAR 连续切换六帧，每个版本独立启动三轮。Qt 离屏环境下的切帧 CPU 耗时中位数从 83 ms 降到 37 ms。该测量止于场景更新，实际 GPU 输出和屏幕刷新另计。
- 体场的自动预算合计所有通道，每个标量按 16 字节可用内存估算。可用内存查询失败时采用 6,400 万个标量的备用预算。等值面提取和颜色映射仍保留原始网格分辨率。

## 复测与分发

使用 [benchmark_large_files.py](../../tools/performance/benchmark_large_files.py) 的 `make` 子命令在空目录内生成输入，`run` 子命令选择 `cube400`、`cube416`、`out`、`xd`、`cp`、`wave`、`companion`、`mesh` 或 `gui`。用 `--source` 指定要测试的源码根目录。完整原始测量和从独立安装的 4.0.0 wheel 重跑的 21 次文件读取结果见 [performance.json](performance.json)。

程序附带 x64 Windows 和 Linux 的可选 C++ 数值解析器。其他体系结构、无法加载原生库或遇到特殊数值格式时，会使用通用解析路径。Windows DLL 在 Linux 上交叉构建并检查了 PE32+ 架构、导出函数和展开表。这一版的运行与性能验证均在 Linux 上完成。

数值内核源码位于 `lele/native/cube_numbers.cpp`。使用 Linux g++ 重建时可执行 `g++ -O3 -std=c++17 -shared -fPIC lele/native/cube_numbers.cpp -o lele/native/cube_linux_x64.so`。使用 x64 MSVC 开发者命令行时可执行 `cl /nologo /std:c++17 /O2 /LD /MT lele/native/cube_numbers.cpp /link /OUT:lele/native/cube_win_x64.dll`。
