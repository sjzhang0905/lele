# LELE 4.2.3 首个结构打开速度

## 启动与首个结构

欢迎页可见区域绘制结束后，后台导入首个结构会用到的组件，包括文件树、结构摘要、轨迹存储、标注和字体，并尝试载入随包的原生坐标与网格读取库。界面线程在最终的画布上准备原子、键和角落坐标轴，此时后台可继续导入其他读取器。提前选文件会优先打开真实结构，跳过等待中的额外导入和演示场景。

普通小分子的近邻筛选使用有上限的原子对枚举。周期结构仍按晶格平移区分候选键，遮挡判断复用同一条有向边的长度，保留原有的短键和近共线判据。相同颜色的换算结果可以复用，逐原子颜色覆盖仍实时生效。

## 对照计时

使用 Linux、Python 3.12.14、PySide6 6.11.3、VTK 9.6.2 和 Mesa 软件 OpenGL。每种打开时机、文件、版本各启动 5 个全新进程，两版交错运行，共 40 个进程。保留系统文件和驱动缓存。计时从调用正常打开入口开始，到文件树、坐标表和视图完成本次更新，包含真实 VTK 绘制。每种结构的两版帧缓冲 RGB 字节摘要一致。

| 操作 | 4.2.2 中位数 | 4.2.3 中位数 | 耗时减少 |
|---|---:|---:|---:|
| 欢迎页显示后立即打开 water.xyz（3 原子） | 0.984 s | 0.392 s | 60.2% |
| Ready 后打开 water.xyz（3 原子） | 0.073 s | 0.072 s | 2.6% |
| 欢迎页显示后立即打开 Si_POSCAR | 0.971 s | 0.871 s | 10.3% |
| Ready 后打开 Cu500.POSCAR（500 原子） | 1.063 s | 0.692 s | 34.9% |

从脚本开始初始化 Qt 到欢迎页完整绘制后的第一个后台启动回调，两个版本各 20 次的中位数为 **0.387 s** 和 **0.375 s**。这组测试覆盖 Linux 源码进程，Windows 开机冷缓存、启动器和实际显卡驱动的耗时需要在对应机器测量。

单独对同一铜超胞的 3,000 条候选边运行遮挡筛选，9 次的中位数从 0.1727 s 降到 0.0182 s。普通分子、周期及大坐标偏移、严格阈值等 118 组键图逐项比对一致。另对 13 个结构或计算样例比对了读取的坐标、晶胞、帧信息、键和短接触，有体场时也核对了网格，有周期性时核对了边界复制和跨胞键。

## 复测

在装有所需依赖的环境中，进入待测 LELE 源码的根目录。下面两条命令分别测欢迎页刚显示就请求文件，以及等到 Ready 后再请求。对各版本计时请使用同一份脚本、同一个 Python 环境和相同的输入文件。每次命令会开启一个新进程。

```text
python tools/performance/benchmark_first_open.py examples/water.xyz --when welcome
python tools/performance/benchmark_first_open.py verification/v4.2.3/Cu500.POSCAR --when ready
```

Windows 桌面使用默认原生 Qt/VTK 窗口。Linux 无显示器环境可增加 `--egl`。JSON 中的 `open_to_render_s` 记录本次更新中已完成的结构绘制，`open_to_updated_s` 还计入界面表格收尾。在此报告的 Linux 计时中使用了 `OPENBLAS_NUM_THREADS=1`、`LP_NUM_THREADS=2` 和 `LIBGL_ALWAYS_SOFTWARE=1`。
