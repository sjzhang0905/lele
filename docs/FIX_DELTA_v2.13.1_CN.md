# LELE v2.13.1：五项增量验收修复

2026-11-03。修复针对 `LELE_v2.13.0_delta_acceptance_20261102(1).zip` 中的五个失败场景，保留 v2.13.0 的 Glossy、Sibyl 配色、欢迎页简化及自动晶轴。

| 报告问题 | 修复后的行为 |
| --- | --- |
| 1. 斜晶胞晶面位点无法打开 | 对树查询使用的分数坐标执行严格的 `[0,1)` 归一化。极小负数取模舍入为 1 时归到等价的 0，树和查询使用相同规则。仅修正匹配坐标，不平移源原子。报告中的斜晶胞及 Ni 位于等价 x=1 的输入均读得 Co 0.6/Ni 0.4。 |
| 2. 占据率导出截断后超过 1 | 原生 CIF 导出使用保留双精度往返值的 17 位有效数字，避免默认四位小数引入的总量 1.0001。Co、Ni、Fe 的 0.1666667、0.1666667、0.6666666 导出重读后各值不变；真实过占据仍报错，不通过放宽阈值或归一化掩盖。 |
| 3. 粘贴无关 C 后跟错 H | 保留存活原子的身份，新粘贴原子使用全新身份，删除后不复用。监视及着色按需要的原子逐项验证映射，缺失的 C 不影响仍存在的 O/H。原有和新建 O–H 监视均为 `[2,2] Å`。涉及被删除 C 的旧监视在该帧留空，新补回的同元素同坐标 C 也不会被当成旧 C。 |
| 4. 交换 O 合并了两个 C 块 | 将 POSCAR 声明块的归属保留到每个原子，按块身份及元素共同重建头部。只交换 O 时，`C C O / 1 1 2` 保持不变。直接交换两个 C、暂时拆开再恢复排列、项目重开及两种 POSCAR 输出也保留边界和固定标记。 |
| 5. 混占 CIF 少数组分被移到末尾 | 导入时记录每个晶位组分的原始行顺序，写出时直接按该顺序输出。`Co,Ni,O` 追加 H 后为 `Co,Ni,O,H`；原输入为非连续的 `Co,O,Ni` 时也保留该顺序。多批新增原子依次追加。删除、LELE 原生复制粘贴及项目保存携带行序；明确重编号时按新的晶位顺序排列，并保留各晶位内部的组分顺序。 |

对于扩胞，原单胞的已有原子保留身份，新副本拥有独立身份；CIF 组分行与 POSCAR 声明块按单胞复制顺序保留。显示对齐、振动选区与配位轨迹也逐项检查所需身份。整体偶极等需要完整参考几何的匹配继续使用完整映射，避免把改变原子组成后的结构当成原计算几何。

CIF 仍以完整展开的 P1 结构导出；周期/对称等价的重复代表统一为同一晶位组分，不复制额外占据率。新的行序、块归属和原子身份保存在 `.lele` 项目中。旧文件或旧项目中已经丢失的精度、原始行序及身份，无法从缺失信息中恢复；需要这些原始信息时应重新打开原始结构文件。

复跑脚本、具体输入/输出及日志见 [验证记录](VALIDATION_v2.13.1.md)。
