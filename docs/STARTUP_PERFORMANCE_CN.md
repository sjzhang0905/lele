# 窗口先显示、随后自动预加载

本启动流程随 LELE 1.1.0 提供。

## 启动流程

1. 只加载 Qt 界面所需模块，先显示完整的欢迎窗口、菜单和鹦鹉动画。
2. 欢迎页标题首次绘制后，在下一轮事件循环中启动后台线程，自动导入 NumPy、
   SciPy、ASE、VTK 和读取/编辑模块。无需打开结构来触发。
3. 导入完成后，回到界面线程创建隐藏的三维画布、渲染器和角落坐标轴组件。
   状态栏由 `Loading components…` 变为 `Ready`，欢迎页继续显示。
4. 用户选择结构时复用已准备好的后端。加载期间选中的文件先排队，准备好后按顺序打开；
   命令行文件同样在窗口显示、预加载完成后自动打开。

加载期间可修改显示预设、背景等设置；这些设置会传递给渲染器。
原生图形上下文在首次显示结构时初始化，文件读取和场景构建仍取决于文件本身。
后台线程只导入模块，不创建 Qt 控件或 VTK 场景对象。
关闭窗口会取消待打开文件；应用退出前会等待正在进行的导入结束，避免在线程仍运行时销毁它。

## 测量

同一 Linux / Python 3.12 / Qt offscreen 环境，每次使用新的 Python 进程，
2026-10-27 使用包含 Atoms 页和新布局的源码运行 5 次取中位数。以下各时间均从应用脚本开始执行计时。

| 阶段 | 耗时中位数 |
|---|---:|
| 应用模块导入 | 111.5 ms |
| 欢迎页首次绘制完成 | 181.2 ms |
| 后台导入及隐藏三维画布准备完成 | 820.4 ms |

5 次运行中，欢迎页首次绘制前均未导入大型科学库；不选择任何结构，程序也会自动完成预加载，
此时已加载 NumPy、SciPy、ASE、VTK，三维画布已创建，文件列表仍为空。

以上为源码运行结果，未清空操作系统文件缓存，不包含点击图标至 Python 开始执行前的开销。
不是 Windows EXE 的实测值；Windows 速度需要重新打包后确认。

## Windows 应用补丁

1. 用这份源码更新原项目目录，重新运行 `build_windows.bat`。
2. 使用本次生成的 `dist\LELE\LELE.exe`。
3. 分发时保留完整的 `dist\LELE` 目录，包括 `_internal`、`LICENSE`、`SOURCE_NOTICE.md`。

更新 Python 源码不会修改已经打包好的 EXE。图标、MIT 许可和原有目录分发方式保持不变。

线程实现依据 Qt 的[线程与对象说明](https://doc.qt.io/qtforpython-6/overviews/qtdoc-threads-qobject.html)
和 [QThread 文档](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html)。
